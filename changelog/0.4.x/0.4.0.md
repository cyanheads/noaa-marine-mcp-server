# 0.4.0 — 2026-09-17

## Added

- **`water_quality`** joins `noaa_marine_find_stations`' `types` filter, matching NDBC sub-surface water-column stations — 140 stations, 45 previously unreachable by any filter (#28)
- **`noaa_marine_find_stations`** matches CO-OPS rows by station ID, not just NDBC; an exact-ID match sorts first when no proximity center is given (#29)
- **`noaa_marine_find_stations`** returns a zero-match search as a success (`total_found: 0`) with a `notice` and an `applied_search` echo of the filters that emptied it, and adds a `sources` block naming any catalog that failed to answer (#31, #21)
- **`noaa_marine_get_conditions`** adds `waves_observed_at` and a staleness `notice` — NDBC writes each sensor block on its own cycle, so a block up to 90 minutes older than `observed_at` is now disclosed instead of silently blended in (#24)
- **`noaa_marine_get_water_level`** adds `predictions_status` and a notice disclosing rejected upstream prediction legs instead of dropping them silently (#21)
- **`noaa-marine-station` resource** returns a typed `errors[]` contract (`station_not_found`, `source_unavailable`) in place of an untyped failure (#21)

## Changed

- **`noaa_marine_get_conditions`** `latitude`/`longitude` are nullable — a station absent from the NDBC catalog now reports unknown coordinates instead of a fabricated `0, 0` (#17)

## Fixed

- **`noaa_marine_get_conditions`** wave fields no longer read `null` when the newest NDBC row is `MM`: each sensor block resolves from the most recent row inside a 90-minute look-back that actually carried it (#24)
- **NDBC parser** decodes XML entities in station names and owners (12 stations affected) and validates timestamps per row — a malformed row is skipped rather than producing a fabricated or unparseable observation time (#20)
- **`noaa_marine_find_stations`** no longer throws `no_results`; a zero-row multi-catalog fan-out raises `sources_unavailable` only when every catalog failed (#31, #21)
