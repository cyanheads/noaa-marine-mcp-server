# 0.6.0 — 2026-09-22

## Added

- **`noaa_marine_get_monthly_means`** — verified monthly tidal datums and extremes for a CO-OPS water-level station, one row per station-month: highest/lowest water, tidal datums (MHHW, MHW, MSL, MTL, MLW, MLLW, DTL), ranges (GT, MN, DHQ, DLQ), lunitidal intervals (HWI, LWI), and CO-OPS's `inferred` code verbatim. Wraps the `monthly_mean` product, sent as `time_zone=lst` and trimmed of the resulting overrun month; empty-string upstream values are omitted rather than parsed to 0. Ranges up to 73,000 days, paged by `offset` ([#33](https://github.com/cyanheads/noaa-marine-mcp-server/issues/33))

## Changed

- **`noaa_marine_find_stations`** — the `types` value `water_level` now names `noaa_marine_get_monthly_means` alongside `noaa_marine_get_water_level` as the tool that reads it ([#33](https://github.com/cyanheads/noaa-marine-mcp-server/issues/33))

## Fixed

- **`noaa_marine_get_water_level`** — an `hourly`, `high_low`, or `daily_mean` window CO-OPS answers with "may not be offered at this station at the requested time" now resolves by window instead of always reading as `verified_data_lag`: a window ending on or after the first day of the prior month is `verified_data_lag`, an earlier one is `no_data`, since waiting cannot help a window before the station's record ([#41](https://github.com/cyanheads/noaa-marine-mcp-server/issues/41))
