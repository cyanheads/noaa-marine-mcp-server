# 0.6.1 — 2026-10-08

## Changed

- **Error results carry a request ID.** Every tool error result has `data.requestId` and its `content[]` text closes with `(reason … · request <id>)`; resource errors carry `data.requestId` too (mcp-ts-core 0.13.10). Declared `recovery` hints are now filled by the framework rather than forwarded by each handler; the hint text callers receive is unchanged.
- **Arguments are repaired before validation.** An integer sent for a string field (`station_id: 46087`) is accepted since mcp-ts-core 0.13.9; a numeric string for a number (`limit: "3"`) and a lone string for an array (`types: "tide"`) since 0.13.14. A boolean sent for a string field is still rejected with `-32602` `invalid_arguments`.
- **`ctx.log` notifications mirrored to the client** honor `MCP_LOG_LEVEL` and mask sensitive fields (mcp-ts-core 0.13.11).
- **`invalid_date_range` description reworded** in `noaa_marine_get_tide_predictions`, `noaa_marine_get_water_level`, `noaa_marine_get_monthly_means`, and `noaa_marine_get_currents`; it appears in the advertised error-reason description. Prose only; no input or output constraint changed.
- **`server.json`** — the npm package entries drop the `run start:*` arguments and set `runtimeHint` to `npx`; the streamable-http entry sets `MCP_TRANSPORT_TYPE` to `http`.
- **Docker image** — dependencies install in a `deps` stage on the build platform with a per-target cross-install (mcp-ts-core 0.13.10), musl-only native packages are pruned from the image (mcp-ts-core 0.13.11), and the base images move from Bun 1.4.0 to 1.4.2. `MCP_FORCE_CONSOLE_LOGGING` is no longer set in the image.
- **Packaging** — the `.mcpb` bundle excludes `/.cache/`, `/coverage/`, and `/tests/`; the npm `files` list excludes `dist/*.mcpb`.
- **Repo config** — `.gitignore` ignores every `.env*` variant except `.env.example`, `.env.template`, and `.env.sample`, and `.dockerignore` excludes `.env*` and the MCP Registry token files from the build context; the CodeQL workflow runs per language and uploads under `/language:<language>`.
- **Telemetry documentation** — `.env.example` and the README document the settings: with `OTEL_ENABLED=true`, `OTEL_EXPORTER_OTLP_ENDPOINT` alone exports traces and metrics to `<base>/v1/traces` and `<base>/v1/metrics`, and no endpoint exports nothing (mcp-ts-core 0.13.7); OTLP log export via `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` and failed-call payload logging via `LOG_TOOL_FAILURE_PAYLOADS` are opt-in (mcp-ts-core 0.13.8). The README tool and capability reference is condensed to match the current tool surface, and `MCP_HTTP_HOST` is listed with its `127.0.0.1` default.
