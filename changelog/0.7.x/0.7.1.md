# 0.7.1 — 2026-10-29

## Added

- **`noaa_marine_get_conditions` reads a 7-digit CO-OPS station ID** through the NDBC station that relays its met sensors (#46). `station_id` is the NDBC station read, the requested ID returns as the new `coops_station_id`, and `notice` names both; a gauge NDBC does not relay stays `buoy_not_found`.
- **`noaa_marine_find_stations` `offset` input and `next_offset` output** (#49). Results sort by unrounded distance, or exact-ID rank then name, then `source` and `station_id`, so pages partition the matches.
- **`NOAA_CLAMP_LIMITS`** (`true` by default) sets how an over-cap `limit` is handled (#49). `false` advertises and enforces each cap as a schema maximum.

## Changed

- **Paging counts rows, not bytes** on `noaa_marine_get_tide_predictions`, `noaa_marine_get_water_level`, `noaa_marine_get_currents`, `noaa_marine_get_monthly_means`, and `noaa_marine_find_stations` (#49). A call with no `limit` now returns a count-sized first page (50 rows, 24 for monthly means, 20 stations) with `next_offset` to continue; a `limit` above its cap (1,000 rows, 200 stations) is clamped with a notice.
- **`noaa_marine_get_water_level` returns `future_window`** for a `begin_date` after the station's local date, with no CO-OPS request (#45). Such windows previously failed as `no_data` or `verified_data_lag`.
- **`datum_unavailable` recovery hints** no longer name the datum CO-OPS just rejected (#50).
- **`noaa_marine_get_ocean_observations` oxygen line** reads `Oxygen saturation: … · Oxygen concentration: …`, so a missing value no longer renders as `not reported saturation` (#51).

## Fixed

- **`noaa_marine_get_water_level` and `noaa_marine_get_monthly_means`** fail a station that has never had a water-level gauge as `no_gauge`, pointing to nearby gauges and tide predictions, instead of a datum-retry hint (#50).
- **`./.env` values apply under Node** (#49). The server config loads `./.env` on its first read.
