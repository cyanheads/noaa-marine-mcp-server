# 0.5.1 — 2026-09-22

## Added

- **`begin_date`/`end_date`** on `noaa_marine_get_tide_predictions`, `noaa_marine_get_water_level`, and `noaa_marine_get_currents` accept `YYYY-MM-DD` alongside `YYYYMMDD`, normalized per field ([#39](https://github.com/cyanheads/noaa-marine-mcp-server/issues/39))

## Changed

- `framework-skills/` synced with `@cyanheads/mcp-ts-core` 0.13.6; `scripts/lint-mcp.ts` reads `lint.truncationAllowlist` from `devcheck.config.json`; `docs/design.md` error-contract table reconciled to the definitions (station and date-range codes, rows for `noaa_marine_get_current_profile` and `noaa_marine_get_ocean_observations`); issue-form field hints shortened

## Fixed

- **`upstream_throttled`** — a CO-OPS HTTP 403 (per-customer throttling) now maps to a retryable `RateLimited` error instead of a bare fetch failure on `noaa_marine_get_tide_predictions`, `noaa_marine_get_water_level`, and `noaa_marine_get_currents`, read from the status before any body classification and costing one upstream request. A 403 on the water-level paired prediction fetch alone still returns the observed series with `predictions_status: "unavailable"` and a notice naming the wait; a throttled station catalog keeps `noaa_marine_find_stations`' `sources_unavailable` and the station resource's `source_unavailable`, whose recovery now names the couple-of-minutes wait ([#37](https://github.com/cyanheads/noaa-marine-mcp-server/issues/37))
- **`residual_summary`** on `noaa_marine_get_water_level` clamps `max_surge`/`max_drawdown` at zero, so a one-sided observation window no longer reports a surge or drawdown that never occurred ([#35](https://github.com/cyanheads/noaa-marine-mcp-server/issues/35))
